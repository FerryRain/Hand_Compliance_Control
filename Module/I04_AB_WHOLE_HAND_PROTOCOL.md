## 1. 共同任务与I04B的新目标

共同任务是在已知完整物体几何的条件下，用四指指腹主动接触并遍历整个物体，
兼顾覆盖、接触连续性、各指参与、自然手形和接触恢复。掌心是位姿参考，任务触面为指腹。

I04B正式目标为：

1. 联合规划手掌/手腕的位置和朝向，以及食指、中指、无名指、拇指的表面落点和指腹朝向。
2. 共同求解7个机械臂关节与16个手关节；各指持续参与目标实现，随曲面主动屈伸。
3. 优先连续贴面滑动和贴面转向；当前搜索无法找到可行路线时，执行经碰撞检查的撤离、调姿和重接触。
4. 短暂单指或全手失联允许恢复；分别记录恢复耗时、恢复后接触人数和新增覆盖。
5. 对瓶身、侧面、肩部、瓶盖及瓶底使用同一实际指腹判据，完成全部原网格顶点与目标的覆盖。
6. 用完整原生轨迹独立重放确认结果，同时报告所有离面、调姿、高力和未完成片段。

“四指共同参与”不要求每个曲率区域始终四指接触；各指率、同时人数、有效滑动与缺口均如实报告。
有限搜索未找到贴面路线不等于证明该路线不存在。覆盖完成与连续性好坏分别评价。

## 2. 保留的实验差异

| 方法 | 方法侧可见的任务目标 | 手指参考的来源 | 当前执行安排 |
| --- | --- | --- | --- |
| I04A-MCC | 仅完整手掌/手腕位姿及其参考轨迹 | 公共自然手形、实测接触MCC和公共传感历史恢复 | 待迁移到统一执行层后重新验证 |
| I04A-DPRef | 与A-MCC相同的手掌/手腕参考；无GT逐指目标 | DPRef生成手指名义参考，其后使用同一约束、MCC与恢复 | 继续暂缓 |
| I04B-MCC | 同源手掌目标，加逐指表面位置、法向/指腹朝向和有限曲面查询 | 手掌与四指联合几何规划，其后使用公共MCC与保护 | 当前整手实现作为迁移来源 |

I04A仍包含MCC与DPRef+MCC两个方法的实验设计；当前只执行MCC的安排不改变这个定义。
A-MCC加入公共历史恢复后，名称为“MCC + shared sensor-history recovery”，不再用旧Pure Passive MCC名称描述新结果。

核心对照项是手指名义动作的产生方式及其可用任务信息。B的逐指位置/朝向目标、有限曲面落点搜索、
多指几何可达性评分和由此产生的联合姿态属于B方法。它们不能通过“共用恢复”隐式传入A。
自然关节范围、与物体无关的屈指软先验和底层力控制参数属于公共部分。

## 3. A/B必须一致的非对照部分

以下是新实验的共同约束，须由同一实现和同一配置提供，不能各复制一份后分别调参。
数值以已核验整手配置为迁移基准；正式配对运行前记录最终公共配置与哈希。

| 公共部分 | 一致性要求 |
| --- | --- |
| 机器人与物体 | 同一FR3+LEAP模型、Mustard已有2.8倍缩放、256件碰撞体、质量、摩擦、执行器和物体位置 |
| 物理环境 | 固定物体、零重力、MuJoCo版本一致，物理步长和原生日志间隔均为2ms |
| 初始化 | 每个配对seed只生成一次公共初态；复制相同qpos、qvel、ctrl、warmstart、时间与控制器初始化状态；各案零覆盖 |
| 外层任务 | 同一完整网格、8192顶点、388目标、覆盖账本定义、目标选择规则、候选顺序和失败预算；GT通过各自目标适配器暴露 |
| 自然手形 | 共用物体无关的自然屈指先验、PIP/DIP软协调、姿态正则和任务关节范围，再与原物理范围相交 |
| 指腹判定 | 共用中央掌侧指腹、朝向、接触点、原始/合格接触力的分类代码；边缘和背面不能取得指腹覆盖 |
| MCC | 同一四指控制核、力目标、质量/阻尼/刚度、法向偏移/速度/加速度限幅及状态交接方式 |
| 卸力与安全 | 相同主动卸力/恢复阈值、持续高力保护、关节/步长限制、非指腹/臂间隙、实态及上一参考双几何检查 |
| 接触恢复 | 同一实测失联触发、稳定确认、历史保存、预载交接、暂停/超时预算和未恢复记账；共享部分只读允许的传感历史 |
| 连续执行 | 共用贴面优先策略、轨迹时间参数化、限速、暂停和调姿执行器；方法提供的几何参考可以不同 |
| 资源与停止 | 同一仿真时长预算、公共搜索次数/超时上限、恢复预算、完成判据及危险停止条件；另报实际计算耗时 |
| 评价与交付 | 同一覆盖算法、各指/同时接触指标、完整时间轴统计、力统计、日志格式、独立核验及视频制作方式 |

迁移基准中的公共数值包括：每指正常目标力1N；MCC虚拟质量0.08、阻尼70、刚度20，
法向偏移上限4mm、速度上限0.25mm/s、加速度上限0.02m/s²。
原始力超过2.5N主动卸力、低于1.2N恢复；原始力达到8N的状态排除覆盖，持续超过12N/20ms触发硬保护。
非指腹3mm、臂部1mm原硬几何间隙保留。混合接触的降力规则、预载及暂停细节也必须共同迁移。

长指共同任务范围为侧摆[-0.18,0.18]、MCP[-0.12,0.85]、PIP[0.10,0.95]、DIP[0.07,0.75]rad；
自然软参考为[0,0.22,0.35,0.22]rad，PIP/DIP软耦合沿用整手配置。自然先验是偏好，实际手形由方法和反馈共同决定。
DPRef未来输出同样经过这些公共范围与安全约束，不为某一方法单独扩大关节或力边界。

### 3.1 同一规划框架与同一轨迹的区别

- A-MCC与未来A-DPRef使用同一条冻结的手掌名义参考轨迹；不得分别运行闭环Oracle后宣称腕输入完全相同。
  公共限速、暂停、恢复和保护可以因实际接触不同而造成不同的执行进度，须分别记录名义参考与实际执行。
- A与B使用同源外层任务、同一几何规划框架和公共约束。B增加逐指目标后，联合求解出的手腕/手指路径允许变化，
  这属于被测方法的作用，不强行要求两组实际手腕轨迹逐值相同。
- 闭环运行后A/B状态和覆盖可以不同。同一Oracle在相同输入下应一致；不同状态下的目标序列变化须记录，
  不能把“同一选择规则”写成“实际目标和轨迹始终完全相同”。
- 公共初始化或Oracle私有几何求解可以使用GT；只通过声明接口给方法侧输出。
  A不得取得B的完整关节参考、逐指几何种子、预测覆盖或每步接触答案。

### 3.2 恢复、推进与信息边界

共享恢复由本方法实际经历的位置、接触力、触点/法向、已施加命令及其历史驱动。
A有接触历史时可沿最近实测法向做同限幅的局部重接触；没有有效历史时，只能按已公开腕参考和机器人自身几何
执行声明的有界接近，或请求新的腕目标，不能查询GT最近指腹落点来补足信息。

B可在自身规划层重新选择四指落点、朝向及联合姿态；该几何重规划单独记为B的任务规划行为。
公共MCC的方程、参数和限幅一致；输入法向的来源必须标明“实测/历史”或“B规划”，不能混淆。
安全模块可以私有查询物体碰撞几何，但不能给A输出用于寻找接触的GT逐指位置、法向或可达手形。

共同的实测人数窗口、暂停、稳定恢复和完成判断使用相同规则。当前B开发版的`expected_contacts`来自几何预测，
迁移时必须与公共执行判据分开；不得直接把该预测作为A的隐含输入，也不得让A/B采用不同的稳定窗口或恢复超时。
公共推进窗口的最终数值须在两侧短段验证后共同冻结，未完成此项前不得标记公共执行层已对齐。
失联本身不判整个实验失败；持续危险状态仍按共同保护停止。

## 4. 一致的结果口径

覆盖只由合格的实际指腹接触产生，使用25mm网格边测地邻域并集；完整分母及覆盖半径在运行前冻结。
几何候选、规划目标、预计支持人数和视频均不增加覆盖。
完成要求8192/8192顶点、388/388目标及至少150ms实际安全接触保持，并由独立重放复核。

所有方法共同报告：

- 全程/滑动阶段各指接触率、至少2/3指和四指同时率；全程口径包含接近、换面、卸力和恢复。
- 每指真实切向运动、严格连续接触段及跨度；不跨指、跨失联拼接，不以静止保持代替滑动。
- 单指及全手失联、最长中断、首次重触/稳定恢复时间、未恢复和终点截尾、恢复后的推进与新增覆盖。
- 覆盖随仿真时间的曲线、共同时间前缀结果、完成时间、换面/调姿及其耗时、规划计算耗时。
- 原始接触力、合格指腹力、高力持续时间、非指腹碰撞/臂自碰、关节范围及危险停止原因。

不要求任何方法始终四指接触，不用单次失联或瞬时力峰给策略整体贴PASS/FAIL标签。
局部实现检查、物理核验通过、覆盖完成和方法性能比较分别记录。
